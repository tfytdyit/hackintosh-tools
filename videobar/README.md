# VideoBar — 4K60 HEVC 顺畅播放器（为这台黑苹果写的）

> 目录：`videobar/`
> 构建：`./build.sh` → 产物 `VideoBar.app`

## 为什么写它

你的 DJI 素材是 **3840×2160 / HEVC / 59.94 fps / 130 Mbps**。我先测了三件事：

| 检查项 | 结果 |
|---|---|
| 文件本身有没有跳帧 | 8176 帧、平均 59.97 fps、中位帧间隔 16.7 ms、**0 跳帧 / 0 重复帧** |
| HEVC 硬件解码 | `VTIsHardwareDecodeSupported` = true（H.264 也 true） |
| 解码速度 | 120 帧 / 1.13 s ≈ **106 fps**（4K60 只需 60） |

结论：文件和硬件都没问题，卡顿来自播放器的渲染/缩放链路。VideoBar 直接用 `AVPlayerLayer`（CoreAnimation 合成、GPU 缩放、硬解直通），并把「是否真的跑满 60fps」做成界面上的实时指标。

实测本机播放该文件：**实时 ×1.000、0 卡顿**（连续 10 秒采样，`--probe` 可复现）。

## 功能

- **播放**：播放/暂停、逐帧步进、±5 秒、拖拽进度条（精确 seek，`tolerance = 0`）
- **列表**：打开一个文件自动加载同目录全部视频（按文件名自然排序），右侧播放列表，播完自动下一个
- **续播**：每个文件记住上次看到的位置（`UserDefaults`），下次打开直接接着看
- **速度**：0.5× / 0.75× / 1× / 1.25× / 1.5× / 2×
- **循环**：单曲循环开关
- **全屏**：`F` 或 ⌃⌘F，双击画面也可切换；播放时控件 2.6 秒自动隐藏，鼠标一动就回来
- **拖放**：文件或整个文件夹拖进窗口即可（文件夹 = 播放列表）
- **顶栏 HUD**：分辨率 / 帧率 / 码率 / 编码 / **硬解还是软解** / **实时倍率**（< 0.97 会变橙色）/ 卡顿次数
- 黑底、无边框标题栏、圆角窗口，暗色下不刺眼

## 用法

```bash
cd videobar
./build.sh                 # 编译打包
open VideoBar.app          # 启动（没有文件时是空状态，拖文件进去）
```

命令行自检（打印媒体信息和实时倍率，不需要图形界面）：

```bash
./VideoBar.app/Contents/MacOS/VideoBar --probe ~/Movies/影音/航拍视频照片/dji_fly_20240722_085138_0018_1721619806799_mastershots.mp4
```

想让它成为默认播放器：把 `VideoBar.app` 拷到 `/Applications`（需要你自己终端里 `cp -R`，我的沙箱不能写 `/Applications`），然后在 Finder 里对视频「显示简介 → 打开方式 → VideoBar → 全部更改」。

### 1.2 修复

- 修掉一个启动崩溃：**App 未运行**时用「打开方式 / 双击视频」启动，macOS 会在窗口创建前投递 open 事件，旧代码对 `window` 强制解包 → `EXC_BAD_instruction`。现在把这类 URL 先排队，等 `applicationDidFinishLaunching` 结束再处理（`appReady` + `pendingURLs`），并关掉窗口状态恢复（`isRestorable = false`）。

## 已知限制

- 本地 ad-hoc 签名（没有开发者证书），首次从 Finder 打开若被拦，右键 →「打开」即可；拷到 `/Applications` 后 LaunchServices 注册更完整
- 没有字幕/多音轨切换、没有 HDR 色调映射（你的素材是 BT.709 SDR，用不到）
- 冷启动时用 `open -a VideoBar <文件>` 偶尔不会把文件带进来（未签名 App 的 LaunchServices 限制）；正常用法是**先开 App 再拖文件**，或 Finder 里对文件选「打开方式」

### 1.3 高速播放：1080p 代理

**问题**：4K60 HEVC 130 Mbps 在这台机器（Intel UHD 630）上用 AVPlayer 播放，实测交付帧率随倍速断崖式下降：

| 倍速 | 需要交付 | 实测交付（原片） |
|---|---|---|
| 1.0× | 60 fps | 58.5–59.9 fps |
| 1.25× | 75 fps | 73.1 fps |
| 1.3× | 78 fps | 28.0 fps |
| 1.5× | 90 fps | 20.6 fps |
| 2.0× | 120 fps | 25.8 fps |

也就是解码/呈现能力上限约 60–75 fps，2× 必然掉一半以上的帧 → 看着就是卡。

**做法**：倍速 ≥1.4 时自动切换到 **1080p H.264 代理文件**播放（解码压力降到约 1/4），实测 2× 能稳定交付 59.9 fps，画面顺滑。

- 代理保存在 `~/Library/Caches/VideoBar/Proxy/<文件名>-<大小>-<mtime>-1080p.mp4`，同一文件只转一次
- 第一次切到 2× 会在后台转码（4K 136s 素材约 3 分钟，`AVAssetExportSession` 1080p H.264），转完自动无缝切换，进度显示在控制条
- 切回 ≤1.25× 会自动换回原片（保留播放位置）
- 设置里可关闭：「2× 以上自动切到 1080p 代理（更流畅）」
- 顶栏右侧出现绿色 `1080p 代理` 小标，表示当前播的是代理

同时修掉的：
- 移除了顶栏的「文件名 + 分辨率/帧率/码率/编解码/硬解/倍率/卡顿」监测信息（按要求删掉）
- 变速时音频改用 `varispeed`（不做音调修正），省下的 CPU 留给解码；高速播放时 UI 刷新降到 2Hz
